# AI Agent Guide: Vibe Docing

## Repository Purpose

This repository defines the idea of vibe docing.

It is not an application codebase. Its purpose is to capture the language, framing, and operating shape of vibe docing as a lightweight documentation practice for AI-assisted software work.

The repository should remain client-, product-, and service-agnostic unless it is intentionally expanded with clearly labelled examples.

## Current Repository Shape

- `README.md` is the current canonical manifesto and overview.
- `AGENTS.md` is the working handoff for future agents editing this repository.

At present, the repository is intentionally minimal. Any expansion should stay proportional to that intent.

## Source Of Truth

- Treat `README.md` as the primary source of truth for the concept definition.
- Treat new files as supporting artefacts unless the repository deliberately evolves into a broader framework or template set.
- Keep a clear distinction between what the repository explicitly claims and what an agent is merely inferring.

## Working Intent

When editing this repository, preserve these qualities:

- Keep the language abstract but grounded.
- Prefer clear structure over dense theory.
- Emphasise traceability, reviewability, and living documentation.
- Avoid turning the concept into rigid process theatre.
- Avoid over-claiming what AI can reliably understand or guarantee.

## Critical Boundaries

- Keep the repository client-, product-, and service-agnostic.
- Do not drift into product-specific methodology unless the repository is intentionally being extended in that direction.
- Do not make the writing sound like a vendor framework, compliance standard, or consulting playbook.
- Do not over-specify implementation mechanics where the point is a transferable pattern.
- Keep additions subtle. The repository should feel usable, not inflated.

## Preferred Change Model

1. Refine the core definition only when the new wording is sharper and simpler.
2. Add supporting structure only when it helps future readers or agents act consistently.
3. Keep examples short and illustrative rather than exhaustive.
4. Favour living guidance and reusable templates over long explanation.
